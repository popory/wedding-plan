# 결혼 준비 대시보드 디자인 개편

## 목표

첨부된 `page.tsx`와 `globals.css`의 카드형 대시보드 디자인을 현재 공개 웨딩 사이트 전체에 적용한다. Google Sheets 자동 동기화, 할 일 필터, 예산 집계, 업체 현황, 일정, 신혼여행 예약 상세는 그대로 유지한다.

## 기준 자료

- 디자인 기준: 사용자가 제공한 임시 `page.tsx`, `globals.css`
- 기능 기준: 저장소의 현재 `app/page.tsx`, `app/globals.css`, `app/generated-data.ts`
- 데이터 기준: Google Sheet `혜린이랑 결혼 준비하기`
- 배포 대상: 기존 GitHub Pages 공개 사이트

첨부 `page.tsx`의 한글 문자열은 깨져 있으므로 그대로 복사하지 않는다. 레이아웃 구조와 시각 스타일만 기준으로 삼고, 화면 문구와 데이터는 현재 저장소 및 최신 시트 값을 사용한다.

## 선택한 접근

디자인 이식과 기존 기능 보존을 함께 수행한다. 첨부 디자인의 JSX 구성과 CSS 체계를 현재 화면에 반영하되, 데이터 생성 및 동기화 경로는 변경하지 않는다.

CSS만 교체하는 방식은 첨부 디자인의 정보 구조를 재현하기 어렵고, 전체 컴포넌트 재설계는 현재 범위에 비해 과도하므로 사용하지 않는다.

## 화면 구조

### 상단 내비게이션

- 화면 상단에 고정된 브랜드 영역과 섹션 내비게이션을 배치한다.
- 내비게이션은 `할 일`, `예산`, `계약`, `일정`, `신혼여행`으로 구성한다.
- Google Sheet 열기 버튼을 유지한다.
- 모바일에서는 메뉴를 한 줄 가로 스크롤로 표시한다.

### 요약 대시보드

- 첫 화면에 예식장명, 예식 일시, 보증 인원, D-day를 표시한다.
- 전체 진행률, 본예식 예상 예산, 신혼집·혼수 별도 합계, 우선순위 높은 미완료 건을 각각 독립 카드로 표시한다.
- 가장 가까운 결제 또는 핵심 일정을 어두운 강조 막대로 표시한다.
- 원규 스튜디오 중도금 마감은 최신 시트 기준인 `2026-07-29`를 사용한다.

### 할 일

- 기존 우선순위 목록과 필터 동작을 유지한다.
- 필터는 `전체`, `높음`, `확인`, `결제`, `결정`, `예약`으로 구성한다.
- 각 행에는 마감일, 우선순위, 제목, 설명, 상태를 표시한다.
- 모바일에서도 제목과 설명이 잘리지 않도록 행 높이가 콘텐츠에 따라 늘어나게 한다.

### 예산

- 목표 예산 대비 예상 예산 비율을 누적 막대로 표시한다.
- 카테고리별 금액을 색상 범례와 함께 표시한다.
- 전세·부대비용과 가구·가전·혼수는 본예식 예산과 분리해 별도 영역에서 관리한다.
- 기존 계산 값과 표시 단위인 `억원`, `만원`을 유지한다.

### 확정 업체

- 더채플앳 청담, 원규 스튜디오, 아델라인스냅, 류필름을 반복 카드로 표시한다.
- 카드에는 업체 유형, 상태, 일정, 총액, 다음 행동을 표시한다.
- 원규 스튜디오에는 촬영일, 최신 결제 상태와 촬영 준비 요약이 노출되도록 동기화 값을 사용한다.

### 일정

- 주요 일정을 날짜순 행 목록으로 표시한다.
- 상태별 색상 표시는 유지하되 레이아웃이 변하지 않도록 상태 영역 너비를 고정한다.
- 일정 데이터는 `generated-data.ts`의 최신 동기화 결과를 사용한다.

### 신혼여행

- 오키나와에서 삿포로로 이어지는 일정과 임시 예산을 별도 강조 영역에 표시한다.
- 기존 항공편과 숙소 예약 상세 카드를 유지한다.
- 예약 상세가 없거나 일부 값이 누락되어도 전체 신혼여행 일정은 정상 표시한다.
- 공개 사이트에는 예약번호, 결제수단, 개인 연락처 등 민감정보를 표시하지 않는다.

### 하단

- 시트 기준일과 Google Sheets에서 수정할 수 있다는 안내를 표시한다.
- 원본 시트 링크를 유지한다.

## 시각 체계

- 배경은 밝은 회색, 주요 콘텐츠는 흰색 카드로 구성한다.
- 본문은 짙은 중성색, 진행 상태는 녹색, 핵심 수치와 링크는 인디고, 주의 항목은 분홍 계열을 사용한다.
- 카드 반경, 테두리, 간격은 첨부 CSS의 값을 기준으로 통일한다.
- 한 화면이 한 가지 색상 계열로만 보이지 않도록 녹색, 인디고, 분홍, 금색을 기능별로 나눈다.
- 표시 글자는 Pretendard와 한국어 시스템 폰트 계열을 사용한다.
- 고정 형식 카드와 상태 표시의 크기를 안정적으로 유지해 데이터 변경 시 레이아웃이 흔들리지 않게 한다.

## 데이터 흐름

1. GitHub Actions 또는 로컬 동기화 명령이 Google Sheet의 공개 범위를 읽는다.
2. `scripts/sync-sheet.mjs`가 값을 정규화해 `app/generated-data.ts`를 생성한다.
3. `app/page.tsx`가 생성된 데이터만 화면에 렌더링한다.
4. 디자인 변경은 데이터 파서와 시트 범위를 변경하지 않는다.
5. 동기화 후에도 같은 컴포넌트 구조가 최신 값을 표시한다.

원규 스튜디오의 상세 안내 전체를 공개 사이트에 새로 노출하지 않는다. 현재 사이트가 사용하는 결제 요약 범위만 반영하고, 연락처나 계좌정보 같은 추가 개인정보는 포함하지 않는다.

## 오류 처리

- 카테고리 예산 합계가 0이면 막대 비율 계산 결과를 0으로 처리한다.
- 필터 결과가 없으면 빈 화면 대신 간단한 빈 상태 문구를 표시한다.
- 예약 상세 배열이 비어 있으면 예약 카드 영역만 생략하고 신혼여행 일정은 유지한다.
- 긴 업체명, 일정 설명, 예약 상세는 줄바꿈하며 컨테이너 밖으로 넘치지 않게 한다.
- 시트 동기화 실패 시 기존 `generated-data.ts`가 유지되는 현재 배포 흐름을 보존한다.

## 반응형 동작

- 데스크톱: 최대 너비 1240px, 요약 카드 다열, 업체 및 예약 카드 다열 배치
- 태블릿: 예산과 카드 목록을 두 열 또는 한 열로 축소
- 모바일: 모든 주요 카드를 한 열로 배치하고 내비게이션은 가로 스크롤 허용
- 모바일에서 D-day, 긴 금액, 업체명, 일정 설명이 겹치거나 잘리지 않아야 한다.
- 화면 너비에 따라 글자 크기를 연속적으로 확대하지 않고 명시적 브레이크포인트를 사용한다.

## 접근성과 상호작용

- 내비게이션과 필터 버튼은 키보드로 조작할 수 있어야 한다.
- 활성 필터는 색상뿐 아니라 `active` 상태로 구분한다.
- 진행 막대에는 현재 비율을 설명하는 접근성 레이블을 유지한다.
- 링크와 버튼은 모바일에서 누르기 쉬운 최소 높이를 확보한다.
- `prefers-reduced-motion` 환경에서는 부드러운 스크롤과 전환 효과를 최소화한다.

## 검증

- `npm run lint`
- `npm test`
- 정적 빌드 성공 여부 확인
- 렌더링된 HTML에 예식장, 최신 원규 중도금 날짜, 신혼여행 항공·숙소 정보가 존재하는지 확인
- 개인정보와 예약번호가 렌더링된 HTML에 없는지 확인
- 데스크톱과 모바일 뷰포트에서 스크린샷 확인
- 내비게이션, 할 일 필터, 시트 링크 동작 확인
- 카드, 텍스트, 상태 표시가 겹치거나 화면 밖으로 넘치지 않는지 확인

## 배포

- 구현과 검증이 끝나면 변경 파일을 Git에 커밋하고 현재 저장소의 GitHub Pages 배포 흐름으로 게시한다.
- 배포 완료 후 공개 URL에서 최신 커밋과 핵심 문구를 다시 확인한다.

## 완료 기준

- 공개 사이트 전체가 첨부 디자인의 카드형 대시보드 스타일로 보인다.
- 기존 Google Sheet 자동 동기화와 모든 현재 섹션이 유지된다.
- 원규 스튜디오 중도금 마감이 `2026-07-29`로 표시된다.
- 데스크톱과 모바일 모두에서 텍스트 겹침과 가로 넘침이 없다.
- 린트, 테스트, 프로덕션 빌드가 성공한다.
- 민감정보가 새로 공개되지 않는다.
