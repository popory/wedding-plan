# 신혼여행 확정 예약 상세 표시 설계

## 목표

결혼 준비 웹페이지의 신혼여행 영역에서 확정된 항공편과 숙소 정보를 바로 확인할 수 있게 한다. 현재 디자인과 일정표 흐름은 유지하며, 예약 식별 정보와 결제 정보는 공개하지 않는다.

## 범위

- 신혼여행 일정표 위에 `확정 예약` 영역을 추가한다.
- 데스크톱에서는 항공편과 숙소 카드를 2열로, 모바일에서는 1열로 표시한다.
- 각 카드는 시트에서 유효한 예약 정보를 읽었을 때만 표시한다.
- 기존 신혼여행 일정, 예산, 준비 체크 항목은 그대로 유지한다.

## 데이터 흐름

1. `scripts/sync-sheet.mjs`가 `신혼여행` 탭의 항공편과 숙소 예약 메모를 읽는다.
2. 공개 가능한 값만 정규화해 `honeymoonBookings` 데이터로 만든다.
3. 동기화 결과를 `app/generated-data.ts`에 기록한다.
4. `app/page.tsx`가 예약 데이터를 가져와 신혼여행 일정표 위에 표시한다.
5. 항공편 또는 숙소 데이터가 없거나 해석할 수 없으면 해당 카드만 생략하고 기존 일정표는 정상 표시한다.

## 표시 내용

### 항공편 카드

- 출발일: 2026년 11월 2일
- 노선: 인천(ICN) 11:30 출발, 오키나와(OKA) 14:00 도착
- 항공사와 편명: 이스타항공 ZE0631
- 좌석 등급: 일반석 Q
- 위탁 수하물: 15kg

### 숙소 카드

- 숙소명: 할레쿨라니 오키나와
- 숙박일: 2026년 11월 5일 체크인, 11월 7일 체크아웃
- 숙박 기간: 2박
- 객실: 디럭스 오션뷰 선셋 윙 킹룸
- 투숙 인원: 성인 2명
- 포함 사항: 조식, Wi-Fi
- 취소 조건: 2026년 10월 28일 전 무료 취소
- 참고 사항: 현지 세금이 별도로 부과될 수 있음

## 화면 구성

- `신혼여행` 제목과 예산 요약 아래, 기존 일정표 위에 `확정 예약` 소제목을 둔다.
- 항공편과 숙소는 같은 정보 계층의 간결한 카드로 구성한다.
- 기존 사이트의 색상, 타이포그래피, 간격을 재사용하고 카드 모서리는 8px 이하로 유지한다.
- 긴 객실명과 취소 문구는 자연스럽게 줄바꿈하며, 모바일에서 가로 스크롤이나 겹침이 생기지 않게 한다.
- 예약 카드 내부에 다른 카드를 중첩하지 않는다.

## 개인정보 보호

다음 정보는 시트 동기화 결과와 공개 웹페이지에 포함하지 않는다.

- 예약 번호와 예약 식별자
- 투숙객 및 탑승객 이름
- 카드 번호, 결제 수단 등 결제 정보
- 원본 PDF 링크 또는 파일 경로

공개 빌드 결과에 위 정보가 들어가지 않았는지 자동 테스트로 확인한다.

## 오류 처리

- 예약 메모 형식이 일부 바뀌어도 읽을 수 있는 필드만 표시한다.
- 필수 값이 부족한 예약은 해당 카드 전체를 숨긴다.
- 예약 카드 생성 실패가 페이지 빌드나 기존 일정표 표시를 막지 않게 한다.

## 검증

- 시트 동기화 후 항공편과 숙소의 공개 필드가 생성되는지 확인한다.
- 정적 Next.js 빌드와 기존 테스트를 실행한다.
- 생성된 HTML에 항공편, 숙소명, 숙박일, 객실, 포함 사항, 취소 조건이 있는지 확인한다.
- 생성된 HTML에 예약 식별자, 이름, 결제 정보가 없는지 확인한다.
- 데스크톱과 모바일 화면에서 카드 배치, 줄바꿈, 겹침 여부를 확인한다.

## 제외 범위

- 신혼여행 예산 금액 변경
- 예약 취소나 변경 기능
- 원본 예약 PDF 공개 또는 다운로드 기능
- 항공편과 숙소 외 예약 유형 추가
